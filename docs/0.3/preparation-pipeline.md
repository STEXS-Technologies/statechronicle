# Preparation ownership and ordered gates

The public `prepare_player` and compatibility planning lanes share
`Executor::execute_inner`; they deliberately differ in ingress policy and
legacy marker handling. Preparation is not a committed result. This table
records current order, not a claim that F2 is complete.

| Stage | Authoritative owner and order |
| --- | --- |
| Protected ingress | Detached signature required; registry policy; reconstruct structural validation; bind principal; authorize. Legacy entry points retain their own documented ingress policy. |
| Envelope | Canonicalize intent; enforce size; check expiry with injected clock. |
| Legacy marker | Compatibility lanes read idempotency and may return empty events. Protected preparation skips the marker store entirely. |
| Authentication | Verify a present signature; check client authority-proof freshness. |
| Scope and state | Tenant scope/existence; state type; profile resolution; route; primary state lookup; profile-directed holder reload; projection type agreement. |
| Conflicts | Expected version, then profile access checks. |
| Custom identity | Registered operation and existing domain/schema pinning. |
| Authority | Required binding; evaluate configured authorities; aggregate policy; preserve unavailable > stale > denied precedence; check aggregate freshness. |
| Reduction | Profile check, apply, output state type and custom domain/schema. Repeated custom decoding is still a later F3 item. |
| Primary commitments | Private `PreparedEventStates`: checked version increment, existing or profile-defined unborn state, existing before hash or canonical unborn hash, canonical after hash. |
| Primary emission | Shared `emit_event` consumes checked commitments; event ID precedes injected timestamp. |
| Companion | Profile target, destination lookup, required source, profile companion reduction, the same checked commitment stage and emitter. |
| Legacy claim | One shared final write only for the legacy claiming lane, after all event construction. Protected preparation never claims. |
| Return | Allocate and return the complete ordered primary/companion event vector; no projection write or dispatch. |

`PreparedEventStates` owns the two complete commitments and has no public
constructor. The emitter cannot take an arbitrary unchecked pair. The extraction
removes the two implementations of version/unborn/hash/event construction and
the second legacy intent-write branch. It preserves profile-specific reduction,
addressing and authorization responsibilities rather than merging their contracts.

Failure ordering matters. Version overflow occurs before unborn-state creation
or event-ID consumption. If a companion fails, the primary event ID may already
have been consumed, as in the original implementation; no event vector or intent
claim escapes. An existing projection's before hash is retained, not silently
recomputed or reinterpreted. Clock/ID callbacks remain host-injected and must not
perform durable writes or dispatch.

`crates/statechronicle-executor/tests/emission_contract.rs` freezes canonical
creation and debit/credit event-vector digests generated by the unmodified
`v0.2.0` production implementation. The same test file executes against both
original and candidate. It also freezes primary/companion version-overflow
refusal, absence of legacy claims and subsequent event-ID consumption. These
planning fixtures use the original test-only permissive signature verifier and
in-memory adapters; they qualify event semantics, not authenticated ingress or
physical durability. Existing protected-ingress and ledger tests cover their
separate boundaries.

This is the first F2 extraction. Remaining work includes the broader typed
preparation stages, independently frozen multi-fault gate/error traces,
protected batch composition and F3 native decode-once execution. Neither the
full F2 phase nor release qualification is complete.
