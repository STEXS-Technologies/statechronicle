# Isolated crate archive checks

Run `python3 scripts/check_packages.py` from a committed checkout with Rust 1.100,
Python 3.12+, full local Git history and populated Cargo caches. It uses locked,
offline Cargo operations and creates no PR, workflow run, tag or publication.

The checker archives the committed library/manifests into a temporary directory
outside the repository. Cargo creates all thirteen publishable `.crate` files.
The usual package verification build is deferred with `--no-verify`; the checker
then performs the stronger all-target test, doctest and strict Clippy sequence
against the actual unpacked archives, rather than only compiling their libraries.

An isolated workspace patches internal crates exclusively to other unpacked
archives. Each resolved StateChronicle manifest must live under that unpacked
root. No application dependency points back at the original source checkout.
The root lockfile bounds the registry package set; isolated resolution may not
add an unrecorded registry package, and its resulting lock must remain unchanged
through compilation. The synthetic workspace copies the committed `clippy.toml`
so strict lint uses the existing policy rather than different tool defaults.
That configuration is qualification policy, not a runtime source dependency.
Source archive hashes must also remain unchanged.

This qualifies package contents and the internal candidate dependency graph in
a temporary directory. It is not a crates.io service test, a promise that the
unreleased APIs exist in published registry versions, or publish approval.
Workspace package versions still read `0.2.0`; final version changes invalidate
the affected package evidence and require rerunning the checker before release.

## Fixtures stay inside their package

The first unpacked umbrella test build failed because tests read files from
parent `ci/` and `docs/` directories. Package generation alone did not expose
this: Cargo's normal verification builds the library, not all included tests.

Five byte-identical reference copies now live under
`crates/statechronicle/tests/fixtures`: original wire/history records, original
native domains, the public validation characterization corpus, its frozen result
manifest and custom-domain conformance vectors. The copies add test data/source,
not production library code. They are deliberately retained so published tests
remain runnable independently; they are not a source-reduction claim.

Their provenance pins paths, Git revision and SHA-256. Before making packages,
the checker compares each copy with both its pinned Git object and the unchanged
current reference. Original frozen fixtures, historical producer evidence and
expected protocol bytes are never regenerated by this step. Keep copies exact;
do not update both sides to erase a failing compatibility test.

Successful and failed runs write command, compiler, source, log, lockfile and
archive hashes under `docs/0.3/evidence/packages/`, which is ignored by Git.
Retain these outputs as build/release artifacts. This gate complements the
[local release driver](release-checks.md), [compatibility matrix](release-compatibility.md)
and standalone tutorials. See the [qualification summary](qualification.md) for
the completed candidate; a package check alone does not establish full release
qualification.
