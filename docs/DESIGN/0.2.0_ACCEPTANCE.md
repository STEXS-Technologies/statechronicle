# StateChronicle 0.2.0 acceptance audit

The release is a domain-extensibility library release. No deployment-specific
runtime, storage implementation, scheduler, or authority service belongs in it.

Completion requires evidence for every gate below. A passing narrow test does
not establish a broader gate, and a finite fuzz campaign is not a proof that
arbitrary inputs are safe.

| Gate | Required evidence |
| --- | --- |
| Native domain models | Independent configuration and equipment implementations, registered without editing library sources |
| Generic execution | Domain-independent validation/reduction dispatch; baseline resource and economic semantics supplied by profiles and compatibility facilities |
| Authority and isolation | Command/operation binding, per-domain/schema dispatch, authorization failures, malformed and substituted metadata rejected |
| Integrity and compatibility | Existing BCS vectors, signatures, roots and proofs preserved; custom-domain vectors; explicit schema migration guidance |
| Persistence neutrality | Existing consumer-owned ports; atomic writes, rollback, retry, replay, conflict and concurrent attempts tested |
| Portable cores | Actual allocation-free transitions, canonical buffer encoding, hashes and proof/signature verification; interoperability with the standard implementation; bare-metal compilation |
| Fault injection | Every library-visible transaction step, preflight authorization/signature failure, rollback failure, commit response loss and restart replay exercised |
| Chaos | Seeded schedules for duplication, reordering, stale versions, cancellations, persistence outages, concurrency and recovery; invariants verified after each action |
| Fuzz | Every manifest target instrumented and run; new transition, portable codec/proof and domain-aware verification targets; persisted corpora and failure artifacts |
| Release checks | Workspace tests, formatting, strict lints/rustdoc, dependency policy, coverage ratchet, packaging and library performance checks |

Fault and chaos adapters live exclusively in test composition roots. An adapter
must own transaction cleanup on drop/cancellation and resolve ambiguous commit
responses through idempotent replay; the library must not report uncommitted
effects as success or retry with a new identity.

Portable APIs accept external observations, canonical bytes, clock values and
key material from callers. They make no assertion about physical truth or
consumer reducer determinism beyond their documented contracts.

## Verified acceptance evidence

The custom-domain integration suite includes independent native profiles,
signed execution/replay/proofs and protocol golden vectors. Durable tests cover
all single-tenant transaction boundaries, rollback failures, cancellation,
competing reservations, payload conflicts and ambiguous commit responses.
Sixteen seeded schedules check atomic persisted effects after 32 actions each.
Eight additional schedules reorder and concurrently deliver a 24-commit,
two-domain history for 64 actions each, inject outages and lost acknowledgements,
then recover using the original identities. Every action checks durable prefixes,
reservations and projection bounds; recovery checks the expected final root.

Generic execution delegates addressing, access, routing, unborn commitments,
companion transitions and event-group validation to profile-owned policies.
Baseline reducers and economic rules live in profiles; settlement coordinators
remain compatibility facilities outside the generic pipeline.

`statechronicle-portable` implements bounded native transitions, canonical
buffer codecs, compatible custom-state/key hashes, strict Ed25519 and borrowed
sparse-Merkle verification. Standard/portable interoperability and sequence
property tests pass. Both portable crates compile independently for bare metal
on stable Rust 1.99; the portable cores were also checked on Rust 1.85.
`scripts/check_embedded.sh` uses stable by default and makes this a release gate.

All 25 manifest fuzz targets completed an instrumented 60-second campaign per
target. The native transition target compares standard/portable configuration
and equipment semantics and verifies replay commitments and tamper rejection.
Corpora, logs and failure artifacts are retained; CI uploads those artifacts.
Finite campaigns establish exercised inputs, not universal safety.

Dependency security/license checks and packaging passed. The performance gate
passed at approximately 4.8 million operations per second with all six baseline
economic scenarios passing their correctness runs.

The implementation and versioned-recovery follow-up passed all 794 finite
workspace tests. The release audit also passed doctests,
formatting, strict Clippy/rustdoc, dependency policy and independent bare-metal
checks. The original 24 targets passed the complete instrumented smoke gate;
the added profile-id target passed its own instrumented campaign. A fresh package directory
verified every publishable crate without relying on stale local archives.
Protocol-surface line coverage is 94.50% against the unchanged 92.4% ratchet;
unfiltered workspace line coverage is 91.37%. Existing coverage exclusions were
retained; newly extracted profile policies/reducers and settlement facilities
remain measured.

The listed release gates are satisfied by this bounded evidence. Publication
is a separate operation. Consumer reducers/codecs remain responsible for their
own determinism, resource bounds and external authority/trust assumptions.

## Follow-up audit

The 2026-10-10 re-audit found and fixed an asymmetric persistence state-type
binding: a custom intent could otherwise accompany a baseline event at this
boundary. Intent and event types now agree in both directions before any
transaction begins. Replay now rejects unsupported event schemas and stored
version-zero projections; regression tests cover each rejection.

Domain selection compares validated `ProfileId` values, operation selection
compares `Operation` values, and state selection uses `StateType`. Native
commands/lifecycle states are consumer enums. Holder selection now compares
`SubjectId` values directly. Production routing does not match error messages.
Wire field names and canonical schema/operation names remain strings at their
parsing or portable boundaries; schema/state versions remain validated numeric
values. No claim is made that every protocol primitive is a newtype.

`fuzz_profile_id` exercises constructors, parsing, length/control-character
bounds, Unicode, JSON/BCS deserializer agreement and canonical binary roundtrips.
Existing operation/status targets cover those newtypes; custom-state, native
transition and portable targets exercise domain/schema substitution and command
binding. This audit found no additional unresolved release blocker. It is not a
proof of universal correctness or the absence of every vulnerability.

The versioned-recovery follow-up registers schemas one and two of the same
configuration domain. It rejects in-place schema substitution, records migration
to a separate resource, loses a commit acknowledgement, retries the original
identity, reconstructs a fresh executor's projections and continues at the
persisted version. Both schema histories replay to the expected cumulative root;
cross-schema decoding and stale-version requests fail. All 794 workspace tests
and strict Clippy pass. This uses the in-memory transaction fixture and does not
establish disk durability or recovery after actual process termination. Consumer
responsibilities are summarized in [the extension guide](DOMAIN_EXTENSIONS.md#consumer-responsibilities-and-remaining-boundaries).
